# 白山秘闻：已击败玉璧后的失败状态修复

本配方来自玩家亲自回档补完任务的真实存档，以及玩家已确认在游戏内成功的结果移植。它是限定状态的失败修复，不覆盖未接任务、未击败玉璧、其他任务路线或后续周目。

## 来源与验证

- 重玩结束前后的连续备份中，任务从 `QC_Started` 变成 `QC_Succeded`，分支 3 从进行中变成完成，并实际获得 `AC_HeavyAttackDamage`（残破容器）。成功记录中 `PBZQuestBranch_4` 仍为 `None`，配方保留这个真实状态。
- 先审查真实完成事件的差异，再移植到原进度的失败档；此外，依据失败档与成功档的对照，移除 `bsmw.剑偶.死亡无任务` 和 `bsmw.毕桃桃.提前死亡`，在全局与组件标签中补上成功标记。这些失败标记的清理是经审查的修复操作，不声称它们来自重玩最后一刻的原始差分。
- 本文件的 JSON 保存最终已验证修复的 16 条操作，使用仓库既有的 `slot_ops` 格式。用 `complete_quest.py` 对两份原始失败槽位离线应用，结果分别与安装时对应槽位的 JSON 完全一致。两份槽位属于同一位玩家、同一轮游戏，并非两个独立玩家的验证。
- 修复容器的 12 个槽位已重新解密、解压并比对；玩家随后读档确认成功。新增加的范围检查仅检查输入，不改变那 16 条已验证操作。
- 不提交原始存档、完整槽位、Steam ID、账号待同步记录或本地路径。

## 适用条件

`requires` 会检查：首周目、指定的失败分支状态、已击败玉璧且已有白山双剑、乌冷霜/毕桃桃相关前置标签、失败结局组件标签和相关 NPC 的对话序列初始值。任何目标不满足条件，命令会在写出任何目标或成就文件前整体报错。不要删掉检查后强行使用。

必须同时使用本 PR 中支持 `requires` 的 `scripts/complete_quest.py`。旧脚本会忽略此字段，不能单独复制 JSON 到旧版本使用。`transplant.py` 的底层 `Patcher` 也不检查此字段。

```bash
python3 -I scripts/complete_quest.py --quest BaiShanMiWen --target TARGET.json --out-dir patched --dry-run
```

确认目标适用后去掉 `--dry-run`，按技能的备份、打包、退出游戏、安装流程进行。配方本身不切换自动存档，不覆盖整个槽位，不把旧进度复制到新进度。

## 修改范围与限制

- 恢复真实的成功任务记录及对应任务时间。
- 只清理两项失败标签，加入对应成功标签；保留同一组件中的幻术琵琶等其他任务标签。
- 同步两个 NPC 的结局序列及三个缺失的完成流程节点。
- 补入基础版残破容器；已有饰品的等级由现有 Patcher 保留。
- 不改变角色数值、材料、主线、其他任务、地图、Boss 击杀记录、已拥有武器、位置及游戏时长。任务/饰品时间戳由 Patcher 限制到目标存档时间。
- `ach_ops` 留空：真实重玩档的饰品收集计数已经达到 30，完成前后没有新增收集记录，无法据此验证未达门槛玩家的计数变化。本配方不推断或伪造 Steam 成就解锁/待同步队列；也不保证补齐未达门槛的本地饰品收集计数。玩家原本已通过重玩获得的 Steam 成就不依赖此配方。
- 重复应用到成功档会被范围检查拒绝。其他失败路线、其他版本、其他玩家及后续周目尚未进行游戏内验证。

## 测试

```bash
python3 -I -m unittest discover -s tests -v
```

测试使用根据公开配方构造的最小数据，不包含玩家存档。覆盖适用/不适用状态、未知检查拒绝、旧配方兼容、其他字段保留，以及多目标输入中有一份不适用时不产生部分输出。
